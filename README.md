# Backtester V2 - Инструкции по установке и запуску (Этап 0-1)

Этот документ описывает шаги для настройки, запуска и базовой проверки функционала приложения Backtester V2, разработанного на Этапах 0 и 1.

## Предварительные требования

Перед началом убедитесь, что у вас установлены:

*   **Docker**: [Инструкция по установке Docker](https://docs.docker.com/engine/install/)
*   **Docker Compose**: Обычно устанавливается вместе с Docker Desktop. [Инструкция](https://docs.docker.com/compose/install/)
*   **Node.js**: Рекомендуется LTS версия. [Скачать Node.js](https://nodejs.org/)
*   **npm**: Обычно устанавливается вместе с Node.js.

## Установка

1.  **Клонируйте репозиторий** (если вы еще этого не сделали):
    ```bash
    git clone <repository_url>
    cd backtesterv2
    ```
2.  **Установите зависимости** (хотя они уже должны быть установлены в процессе разработки, на всякий случай):
    ```bash
    # В корневой директории проекта
    cd backend
    npm install
    cd ../frontend
    npm install
    cd ..
    ```
3.  **(Важно) Создайте файл `.env` для Backend:**
    *   Перейдите в директорию `backend`.
    *   Попробуйте скопировать файл `.env.example` (если он был создан автоматически) и переименовать копию в `.env`:
        ```bash
        # Находясь в директории backend
        cp .env.example .env
        ```
    *   **Если `.env.example` не был создан автоматически** (из-за возможных ограничений безопасности), создайте файл `backend/.env.example` и `backend/.env` вручную со следующим содержимым:
        ```dotenv
        NODE_ENV=development
        PORT=5000
        
        # PostgreSQL Database (значения используются, если не переопределены в docker-compose)
        DB_HOST=db
        DB_PORT=5432
        DB_USERNAME=user
        DB_PASSWORD=password
        DB_DATABASE=backtester_db
        
        # Redis (значения используются, если не переопределены в docker-compose)
        REDIS_HOST=redis
        REDIS_PORT=6379
        
        # OKX API (Optional - for future use if needed beyond public data)
        # OKX_API_KEY=
        # OKX_API_SECRET=
        # OKX_API_PASSPHRASE=
        ```
    *   **Примечание:** В текущей конфигурации `docker-compose.yml` переменные окружения для базы данных и Redis уже заданы в секции `environment` сервиса `backend`. Файл `.env` пока не используется напрямую Docker'ом (строка `volumes` закомментирована), но он нужен для локальной разработки и может понадобиться в будущем. Убедитесь, что значения в `docker-compose.yml` соответствуют вашим ожиданиям.

## Запуск приложения

Проект использует Docker Compose для управления окружением.

### Режим Разработки (с Hot Reloading для Frontend)

1.  Убедитесь, что Docker Desktop запущен.
2.  В корневой директории проекта выполните:
    ```bash
    docker-compose -f docker-compose.yml -f docker-compose.override.yml up --build
    ```
    *   Флаг `--build` нужен при первом запуске или после изменений в `Dockerfile`, `package.json` или базовых зависимостях.
    *   В последующие разы можно использовать `docker-compose -f docker-compose.yml -f docker-compose.override.yml up`.
3.  **Frontend** будет доступен на [http://localhost:5173](http://localhost:5173) с включенным Hot Module Replacement (HMR) благодаря Vite.
4.  **Backend API** доступен на [http://localhost:5000](http://localhost:5000). Запросы от Frontend (с `localhost:5173`) будут проксироваться на бэкенд благодаря настройке в `frontend/vite.config.ts`.

### Режим Production (сборка Frontend и раздача через Nginx)

1.  Убедитесь, что Docker Desktop запущен.
2.  В корневой директории проекта выполните:
    ```bash
    docker-compose up --build
    ```
    *   Эта команда использует только `docker-compose.yml`.
    *   Frontend будет собран с помощью `npm run build` и будет раздаваться через Nginx.
3.  **Frontend** будет доступен на [http://localhost:8080](http://localhost:8080).
4.  **Backend API** доступен на [http://localhost:5000](http://localhost:5000).

## Остановка приложения

*   Нажмите `Ctrl + C` в терминале, где запущен `docker-compose`.
*   Для остановки и удаления контейнеров: `docker-compose down` (если запускали production) или `docker-compose -f docker-compose.yml -f docker-compose.override.yml down` (если запускали development).
*   Для удаления контейнеров и томов (volumes): добавьте флаг `-v` к команде `down`.

## Текущее состояние UI (Frontend)

*   Реализован базовый макет (`frontend/src/layouts/DefaultLayout.vue`) с боковой панелью навигации (PrimeVue `PanelMenu`).
*   Созданы страницы-заглушки или базовые версии для разделов: Home, Управление данными, Очередь задач, Бектестер, Сканнер, Настройки.
*   Страница **Очередь задач (`/queue-manager`)**: 
    *   Отображает счетчики задач по статусам в виде карточек (PrimeVue `Card`) в грид-раскладке.
    *   Отображает таблицу задач (PrimeVue `DataTable`) с возможностью просмотра деталей, повторного запуска и удаления задач.
    *   Реализована фильтрация задач по статусу.
    *   Счетчики задач получают данные с бэкенда, но могут отображать нули, если бэкенд не возвращает данные или в очередях нет задач.
*   Страница **Управление данными (`/data`)**:
    *   Содержит кнопки для запуска фоновых задач по загрузке списка пар и исторических свечей.
    *   Реализована форма для указания параметров загрузки свечей.

## Dockerfiles

В проекте используются следующие Dockerfile для контейнеризации приложений:

*   **`backend/Dockerfile`**: Отвечает за сборку и запуск Node.js бэкенд-приложения.
    *   Использует многоэтапную сборку.
    *   На первом этапе устанавливает зависимости и компилирует TypeScript (если применимо).
    *   На втором этапе копирует скомпилированное приложение и запускает его.
*   **`frontend/Dockerfile`**: Отвечает за сборку Vue.js фронтенд-приложения и его сервировку через Nginx.
    *   **Этап 1 (`builder`)**: Использует образ `node:lts-alpine`.
        *   Устанавливает зависимости `npm install`.
        *   Собирает статические файлы приложения `npm run build`.
    *   **Этап 2**: Использует образ `nginx:stable-alpine`.
        *   Копирует собранные статические файлы из этапа `builder`.
        *   Запускает Nginx для раздачи статики на порту 80.

Для разработки фронтенда с hot-reloading используется `docker-compose.override.yml`, который переопределяет команду запуска контейнера `frontend` на `npm run dev -- --host` и монтирует локальные исходные файлы в контейнер.

## Проверка функционала (Этап 1)

1.  **Откройте Frontend** в браузере: [http://localhost:8080](http://localhost:8080)
2.  **Перейдите на страницу "Data"**, используя верхнее меню навигации.
3.  **Проверка загрузки списка пар:**
    *   Найдите секцию "Fetch Trading Pairs".
    *   Нажмите кнопку "Fetch Pairs".
    *   Должно появиться всплывающее уведомление (Toast) о том, что задача добавлена в очередь, с указанием ID задачи.
    *   В логах контейнера `backtester-backend` (в терминале, где запущен `docker-compose up`) вы должны увидеть сообщения о добавлении и обработке задачи `fetch-pairs`, а также о получении пар от OKX и их сохранении.
4.  **Проверка загрузки свечей:**
    *   Найдите секцию "Fetch Historical Candles".
    *   Введите символ существующей фьючерсной/swap пары OKX в поле "Symbol", например `BTC-USDT-SWAP`.
    *   Оставьте таймфрейм по умолчанию (`15m`) или введите другой поддерживаемый (например, `1h`, `4h`).
    *   Даты начала/конца и лимит можно оставить пустыми (загрузятся последние 100 свечей) или задать.
    *   Нажмите кнопку "Fetch Candles".
    *   Должно появиться всплывающее уведомление о добавлении задачи в очередь.
    *   В логах контейнера `backtester-backend` вы должны увидеть сообщения о добавлении и обработке задачи `fetch-candles` для указанной пары/таймфрейма, получении свечей от OKX и их сохранении в БД.
5.  **(Опционально) Проверка базы данных:**
    *   Вы можете подключиться к базе данных PostgreSQL, используя любой SQL-клиент (например, DBeaver, pgAdmin).
    *   Данные для подключения (если подключаться напрямую к порту, проброшенному Docker):
        *   Хост: `localhost`
        *   Порт: `5432`
        *   База данных: `backtester_db`
        *   Пользователь: `user`
        *   Пароль: `password`
    *   Выполните запросы, чтобы проверить наличие данных в таблицах:
        ```sql
        SELECT * FROM trading_pairs LIMIT 10;
        SELECT * FROM candles WHERE "tradingPairId" = (SELECT id FROM trading_pairs WHERE symbol = 'BTC-USDT-SWAP') ORDER BY timestamp DESC LIMIT 10;
        ```
