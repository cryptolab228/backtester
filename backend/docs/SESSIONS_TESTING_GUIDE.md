# Руководство по тестированию новой системы сессий

## Предварительная проверка

### 1. Проверка API эндпоинтов

**Проверь, что сервер запущен:**
```bash
curl http://localhost:3000/api/scanner/scanner-status
```

Ожидаемый ответ:
```json
{
  "success": true,
  "data": {
    "status": "idle" или "running",
    "sessionId": null или "uuid",
    "hasActiveSession": false или true
  }
}
```

**Получить список сессий:**
```bash
curl http://localhost:3000/api/scanner/sessions
```

### 2. Откройте фронтенд

Перейди на: `http://localhost:5173/sessions`

---

## Тестовые сценарии

### Сценарий 1: Создание и запуск новой сессии ✨

**Шаги:**
1. Открой страницу `/sessions`
2. Нажми кнопку **"Новая сессия"**
3. Заполни форму:
   - Название: `Тест BTCUSDT 1h`
   - Заметки: `Первый тест новой системы сессий`
   - Биржа: `Bybit`
   - Пары: `BTCUSDT, ETHUSDT` (через запятую)
   - Таймфреймы: отметь `1h`, `4h`
4. Нажми **"Создать сессию"**
5. В диалоге подтверди **"Запустить сканнер?"** → Да

**Ожидаемый результат:**
- ✅ Модальное окно закрывается
- ✅ В `SessionSelector` статус меняется на "Сканер работает"
- ✅ Отображается активная сессия
- ✅ Кнопка "Остановить" доступна

**Проверь в логах:**
```
✓ Session created by user
✓ Scanner started with session: [uuid]
```

---

### Сценарий 2: Проверка изоляции данных 🔒

**Шаги:**
1. Создай первую сессию: `Session A - BTC`
   - Пары: `BTCUSDT`
   - Запусти сканнер
2. Дождись появления сигналов/сделок (5-10 минут)
3. Останови сканнер
4. Создай вторую сессию: `Session B - ETH`
   - Пары: `ETHUSDT`
   - Запусти сканнер
5. Дождись появления сигналов/сделок
6. Открой детали обеих сессий

**Ожидаемый результат:**
- ✅ Session A содержит только сделки по BTCUSDT
- ✅ Session B содержит только сделки по ETHUSDT
- ✅ Метрики разные для каждой сессии
- ✅ При переключении между сессиями данные не смешиваются

---

### Сценарий 3: Восстановление после перезапуска 🔄

**Шаги:**
1. Запусти сканнер с сессией
2. Открой страницу `/sessions` и убедись, что сессия активна
3. Останови backend сервер (Ctrl+C в терминале)
4. Перезапусти: `npm run dev`
5. Проверь логи

**Ожидаемый результат в логах:**
```
✓ Restoring last active session...
✓ Session restored: [uuid]
✓ Restored N open positions from session
✓ Closed M phantom position(s)
✓ Scanner started with session: [uuid]
```

**Проверь на фронтенде:**
- ✅ Сканнер автоматически запустился
- ✅ Та же сессия активна
- ✅ Открытые позиции восстановлены
- ✅ В сессии появился флаг `autoStarted: true`

---

### Сценарий 4: Принудительное завершение сессии ⛔

**Шаги:**
1. Запусти сканнер с сессией
2. Открой страницу `/sessions`
3. Найди активную сессию в списке
4. Нажми кнопку **"Завершить"**
5. Подтверди действие

**Ожидаемый результат:**
- ✅ Сканнер останавливается
- ✅ Статус сессии меняется на `completed`
- ✅ В `SessionSelector` статус "Сканер остановлен"
- ✅ Можно создать новую сессию

---

### Сценарий 5: Просмотр деталей сессии 📊

**Шаги:**
1. Открой страницу `/sessions`
2. Кликни на любую завершённую сессию

**Ожидаемый результат:**
- ✅ Отображаются метрики:
  - Всего сделок
  - Открытых/Закрытых
  - Винрейт
  - Общий PnL
  - PnL %
  - Profit Factor
  - Max Drawdown
- ✅ Информация о сессии:
  - Статус
  - Биржа
  - Пары
  - Таймфреймы
  - Даты начала/окончания
- ✅ Таблица последних 50 сделок:
  - Пара, направление, цены входа/выхода
  - Размер позиции
  - PnL в $ и %
  - Статус

### Сценарий 6: Фильтрация сессий 🔍

**Шаги:**
1. Создай несколько разных сессий (минимум 3)
2. Открой страницу `/sessions`
3. Используй фильтры:
   - Статус: `Завершенные`
   - Источник: `Сканнер`
   - От даты: вчерашний день
   - До даты: сегодня

**Ожидаемый результат:**
- ✅ Список обновляется согласно фильтрам
- ✅ Отображаются только соответствующие сессии
- ✅ Счётчик сессий корректен

---

### Сценарий 7: Автообновление статуса ♻️

**Шаги:**
1. Открой страницу `/sessions`
2. В другой вкладке останови/запусти сканнер через API или другую страницу
3. Дождись автообновления (5 секунд)

**Ожидаемый результат:**
- ✅ Статус сканера обновляется автоматически
- ✅ Активная сессия обновляется
- ✅ Счётчики сделок/метрик обновляются

## Проверка API напрямую

### Получить активную сессию
```bash
curl http://localhost:3000/api/scanner/sessions/active
```

### Создать сессию
```bash
curl -X POST http://localhost:3000/api/scanner/sessions \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Test Session API",
    "notes": "Created via API",
    "exchange": "bybit",
    "pairs": ["BTCUSDT"],
    "timeframes": ["1h"]
  }'
```

### Запустить сканнер с сессией
```bash
curl -X POST http://localhost:3000/api/scanner/start/{SESSION_ID}
```

### Остановить сканнер
```bash
curl -X POST http://localhost:3000/api/scanner/stop
```

### Получить метрики сессии
```bash
curl http://localhost:3000/api/scanner/sessions/{SESSION_ID}/metrics
```

### Получить сделки сессии
```bash
curl http://localhost:3000/api/scanner/sessions/{SESSION_ID}/trades?limit=50
```

## Проверка базы данных

### Просмотр сессий
```sql
SELECT id, name, status, "autoStarted", "startedAt", "endedAt"
FROM trading_sessions
ORDER BY "createdAt" DESC
LIMIT 10;
```

### Просмотр сделок по сессии
```sql
SELECT id, pair, direction, "entryPrice", "exitPrice", "realizedPnl", status
FROM session_trades
WHERE session_id = 'YOUR_SESSION_ID'
ORDER BY "createdAt" DESC;
```

### Просмотр метрик
```sql
SELECT 
  ts.name,
  sm."totalPnl",
  sm."winRatePct",
  sm."tradeCount",
  sm."openPositions"
FROM session_metrics sm
JOIN trading_sessions ts ON sm.session_id = ts.id
ORDER BY ts."createdAt" DESC;
```

### Проверка внешних ключей
```sql
-- Должны быть session_id (не sessionId)
SELECT column_name 
FROM information_schema.columns 
WHERE table_name IN ('session_trades', 'session_metrics')
  AND column_name LIKE '%session%';
```

## Troubleshooting

### Сканнер не запускается
1. Проверь логи: `backend/logs/error.log`
2. Убедись что нет активной сессии: `curl http://localhost:3000/api/scanner/sessions/active`
3. Проверь что миграции применены: см. секцию "Проверка базы данных"

### Данные не изолируются между сессиями
1. Проверь что `session_id` правильно сохраняется в `session_trades`
2. Убедись что API возвращает данные с фильтром по `sessionId`
3. Проверь логи на предмет ошибок восстановления

### Сессия не восстанавливается после перезапуска
1. Проверь что была сессия со статусом `running`
2. Проверь что прошло не более 24 часов с последнего запуска
3. Смотри логи на этапе `Restoring last active session`

### Фантомные позиции не закрываются
1. Убедись что `validateAndClosePhantomPositions` вызывается при восстановлении
2. Проверь что SL/TP были установлены для позиций
3. Проверь логи: должно быть сообщение о закрытии фантомных позиций
