# Как работают торговые сессии — простым языком

## 📚 Что такое сессия?

**Торговая сессия** — это как "запись видео" вашей торговой деятельности. Когда вы запускаете сканер или бэктест, система создаёт новую сессию и начинает записывать в неё всё, что происходит.

### Аналогия

Представьте, что вы открываете **тетрадь для записей**:
- **Обложка тетради** = сессия (когда началась, какие настройки использовались)
- **Страницы** = каждая сделка (вход, выход, прибыль/убыток)
- **Итоги на последней странице** = метрики сессии (общая прибыль, винрейт, Шарп)

## 🏗️ Структура системы сессий

```
┌─────────────────────────────────────────────────────────┐
│              ТОРГОВАЯ СЕССИЯ (TradingSession)           │
│  "Контейнер для всей торговой активности"               │
├─────────────────────────────────────────────────────────┤
│  📋 Основная информация:                                │
│    • ID сессии (уникальный)                             │
│    • Дата начала / дата окончания                       │
│    • Источник: scanner / backtester                     │
│    • Режим: demo / testnet / live / backtest            │
│    • Статус: running / completed / interrupted          │
│    • Торговые пары (BTCUSDT, ETHUSDT...)                │
│    • Таймфреймы (1h, 4h...)                             │
│    • Снимок настроек (стратегия, риск-менеджмент)       │
└─────────────────────────────────────────────────────────┘
            │
            ├──────────────────┬──────────────────┐
            ▼                  ▼                  ▼
┌─────────────────┐  ┌─────────────────┐  ┌─────────────────┐
│ СДЕЛКИ          │  │ МЕТРИКИ         │  │ REDIS КЭШ       │
│ (SessionTrade)  │  │ (SessionMetrics)│  │ (ExecutionRec)  │
├─────────────────┤  ├─────────────────┤  ├─────────────────┤
│ Сделка #1       │  │ Общий PnL       │  │ Открытые        │
│ Сделка #2       │  │ Винрейт         │  │ позиции         │
│ Сделка #3       │  │ Sharpe ratio    │  │ (быстрый        │
│ ...             │  │ Макс. просадка  │  │  доступ)        │
│ Сделка #N       │  │ Кол-во сделок   │  │                 │
└─────────────────┘  └─────────────────┘  └─────────────────┘
```

## 🔄 Жизненный цикл сессии

### 1️⃣ **Создание сессии** (при старте)

**Что происходит:**
```
[Запуск сканера/бэктестера]
         ↓
SessionManager.createSession({
  source: 'scanner',        ← Кто запустил
  mode: 'demo',             ← Режим работы
  pairs: ['BTCUSDT', ...],  ← Торговые пары
  strategyParams: {...}     ← Настройки стратегии
})
         ↓
[Создаётся запись в БД]
         ↓
[Создаётся связанная таблица метрик]
         ↓
✅ Сессия готова к работе
```

**Зачем это нужно:**
- Знать, какие настройки использовались
- Группировать все сделки вместе
- Отделять результаты разных торговых периодов

---

### 2️⃣ **Запись сделок** (во время работы)

**Что происходит при открытии позиции:**
```
[Сканер находит сигнал]
         ↓
[Проверяет подтверждение]
         ↓
[Открывает позицию на бирже]
         ↓
SessionManager.recordTrade({
  pair: 'BTCUSDT',
  direction: 'long',         ← Направление (long/short)
  entryPrice: 30000,         ← Цена входа
  size: 0.1,                 ← Размер позиции
  stopLoss: 29500,           ← Стоп-лосс
  takeProfit: 31500,         ← Тейк-профит
  signalId: '...',           ← ID сигнала
})
         ↓
[Записывается в session_trades]
         ↓
[Добавляется в Redis для быстрого доступа]
         ↓
✅ Позиция отслеживается
```

**Что происходит при закрытии позиции:**
```
[Цена достигает TP/SL или получен сигнал выхода]
         ↓
SessionManager.closeTrade({
  tradeId: '...',
  exitPrice: 31500,          ← Цена выхода
  exitReason: 'take_profit', ← Причина закрытия
  realizedPnl: 150,          ← Реализованная прибыль
  realizedPnlPct: 5.0,       ← В процентах
})
         ↓
[Обновляется запись в session_trades]
         ↓
[Удаляется из Redis (уже не открыта)]
         ↓
[Обновляются метрики сессии]
         ↓
✅ Сделка закрыта и учтена в статистике
```

---

### 3️⃣ **Обновление метрик** (постоянно)

**Что происходит:**
```
[После каждой закрытой сделки]
         ↓
SessionManager.updateSessionMetrics(sessionId)
         ↓
[Загружает все закрытые сделки сессии]
         ↓
[Подсчитывает:]
  • Общий PnL (сумма всех прибылей/убытков)
  • Винрейт (% прибыльных сделок)
  • Sharpe ratio (эффективность с учётом риска)
  • Максимальную просадку
  • Средний PnL на сделку
         ↓
[Сохраняет в session_metrics]
         ↓
✅ Метрики актуальны
```

**Зачем это нужно:**
- Видеть текущую производительность в реальном времени
- Сравнивать разные торговые периоды
- Оценивать эффективность стратегии

---

### 4️⃣ **Восстановление после перезапуска** (новое!)

**Проблема:**
Раньше при перезапуске сервера:
- Открытые позиции исчезали из интерфейса
- Если позиция закрылась во время простоя, PnL не учитывался
- Приходилось вручную разбираться, что произошло

**Решение:**

```
[Сервер перезапускается]
         ↓
SessionManager.restoreLastActiveSession()
         ↓
[Ищет последнюю сессию со статусом 'running']
         ↓
Если сессия свежая (< 24 часов):
  ↓
  SessionManager.restoreAndValidateOpenPositions(sessionId)
  ↓
  [Загружает все позиции со статусом 'open']
  ↓
  [Проверяет каждую позицию:]
    • Если старше 7 дней → закрывает как stale
    • Если валидная → восстанавливает
  ↓
  ExecutionManager.restorePosition(trade)
  ↓
  [Добавляет позицию в Redis]
  ↓
  ExecutionManager.validateAndClosePhantomPositions()
  ↓
  [Получает свечи с момента входа в позицию]
  ↓
  [Проверяет каждую свечу:]
    • Сработал ли TP? → Закрывает с профитом
    • Сработал ли SL? → Закрывает с убытком
  ↓
  [Обновляет метрики сессии]
  ↓
  ✅ Все позиции восстановлены, фантомные закрыты с PnL

Если сессия старая (> 24 часов):
  ↓
  [Помечает как 'interrupted']
  ↓
  [Создаёт новую сессию]
  ↓
  ✅ Чистый старт
```

---

### 5️⃣ **Завершение сессии** (при остановке)

**Что происходит:**
```
[Пользователь останавливает сканер]
         ↓
SessionManager.endSession(sessionId, 'completed')
         ↓
[Обновляет статус в БД]
         ↓
[Сохраняет финальные метрики]
         ↓
✅ Сессия завершена и доступна для анализа
```

## 📊 Где хранятся данные

### PostgreSQL (долгосрочное хранение)

| Таблица            | Что хранит                          | Пример                                  |
|--------------------|-------------------------------------|-----------------------------------------|
| `trading_sessions` | Информация о сессиях                | ID, дата, статус, настройки             |
| `session_trades`   | Все сделки                          | Пара, вход, выход, PnL, причина закрытия|
| `session_metrics`  | Агрегированные метрики              | Общий PnL, винрейт, Sharpe, просадка    |

### Redis (быстрый доступ)

| Ключ                        | Что хранит                     | Для чего                          |
|-----------------------------|--------------------------------|-----------------------------------|
| `scanner:positions:open`    | Открытые позиции               | Быстрая проверка TP/SL            |
| `scanner:executions`        | История исполнений             | Отображение в реальном времени    |
| `scanner:signal:*`          | Детектированные сигналы        | Подтверждение и фильтрация        |

## 🎯 Зачем нужна система сессий?

### 1. **Организация данных**
Без сессий все сделки свалены в кучу. С сессиями — каждый торговый период изолирован.

**Пример:**
```
❌ Без сессий:
  Сделка BTCUSDT +100$
  Сделка ETHUSDT -50$
  Сделка BTCUSDT +80$
  → Непонятно, к какому периоду относится

✅ С сессиями:
  Сессия #1 (16.10.2025, demo):
    - BTCUSDT +100$
    - ETHUSDT -50$
    Итого: +50$
  
  Сессия #2 (17.10.2025, live):
    - BTCUSDT +80$
    Итого: +80$
```

### 2. **Сравнение производительности**
Можно сравнить, как работает стратегия:
- В разные периоды времени
- С разными настройками
- На разных режимах (demo vs live)

### 3. **Восстановление после сбоев**
Система точно знает, что происходило до перезапуска:
- Какие позиции были открыты
- Какие настройки использовались
- Какой был текущий PnL

### 4. **Аудит и аналитика**
Вся история сохраняется в БД:
- Когда и зачем была открыта сделка
- Какой был сигнал
- Почему закрылась
- Сколько времени была в рынке

### 5. **Соответствие реальности**
Фантомные позиции больше не искажают статистику:
- Если позиция закрылась во время простоя → система это обнаружит
- PnL будет посчитан корректно
- Метрики будут точными

## 🐛 Анализ текущих ошибок в логе

### Проблема #1: `столбец "session_id" не существует`

**Количество:** 22 ошибки (строки 1-26)

**Причина:**
В БД колонка называется `sessionId` (camelCase), а TypeORM ищет `session_id` (snake_case).

**Решение:**
```sql
-- Применить миграцию:
ALTER TABLE session_metrics RENAME COLUMN "sessionId" TO session_id;
ALTER TABLE session_trades RENAME COLUMN "sessionId" TO session_id;
```

**Когда происходит:**
- При создании новой сессии (ScannerBootstrap)
- При сохранении бэктеста (BacktestSessionService)
- При запросе сессии через API (SessionRoutes)

---

### Проблема #2: `столбец SessionTrade.direction не существует`

**Количество:** 14 ошибок (строки 27-37)

**Причина:**
Добавлено поле `direction` в модель TypeORM, но не добавлено в БД.

**Решение:**
```sql
-- Применить миграцию:
ALTER TABLE session_trades ADD COLUMN IF NOT EXISTS direction TEXT;
CREATE INDEX IF NOT EXISTS idx_session_trades_direction ON session_trades(direction);
```

**Когда происходит:**
- При восстановлении открытых позиций после перезапуска
- При попытке загрузить направление сделки

---

### Проблема #3: `redis is not defined`

**Количество:** 1 ошибка (строка 23)

**Причина:**
Старый код пытался использовать несуществующий импорт `@/services/redisClient`.

**Решение:**
Уже исправлено — используется `connection.duplicate()` вместо глобального `redis`.

## 📖 Полезные команды

### Просмотр активных сессий
```sql
SELECT id, source, mode, status, created_at, ended_at 
FROM trading_sessions 
WHERE status = 'running' 
ORDER BY created_at DESC;
```

### Просмотр открытых позиций
```sql
SELECT st.id, st.pair, st.direction, st.entry_price, st.position_size, st.entry_timestamp
FROM session_trades st
WHERE st.status = 'open'
ORDER BY st.entry_timestamp DESC;
```

### Просмотр метрик сессии
```sql
SELECT 
  ts.id,
  ts.source,
  ts.mode,
  sm.total_pnl,
  sm.win_rate_pct,
  sm.trade_count,
  sm.max_drawdown_pct
FROM trading_sessions ts
LEFT JOIN session_metrics sm ON sm.session_id = ts.id
ORDER BY ts.created_at DESC
LIMIT 10;
```

## 🎓 Заключение

**Торговая сессия** — это не просто "техническая деталь". Это **фундамент** всей системы трейдинга:

✅ Организует данные  
✅ Сохраняет историю  
✅ Позволяет восстанавливать состояние  
✅ Обеспечивает точность метрик  
✅ Даёт полный аудит действий  

После исправления ошибок в БД система будет работать на 100% — все позиции будут отслеживаться, восстанавливаться после перезапуска и корректно закрываться с подсчётом PnL.
