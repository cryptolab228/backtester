# Исправление Алгоритма Портфолио-Бэктеста

## Проблема

В мультитесте (портфолио-бэктест) возникала ошибка: если для одной или нескольких пар не было данных в базе данных, система не загружала их через API, а сразу запускала симуляцию без данных для этих пар.

### Симптомы
- Для пары RVNUSDT найдено 0 свечей в БД
- Система логировала: "No data in DB for RVNUSDT - may need API fetch"
- Но затем принимала решение: "Using DATABASE data (80.0% coverage). Skipping API fetch for performance"
- Симуляция запускалась без данных для RVNUSDT → 0 сделок для этой пары

### Корневая причина
Алгоритм принятия решения основывался только на **покрытии пар** (% пар с данными), но не учитывал два критически важных условия:
1. Некоторые пары могут **полностью отсутствовать** в базе данных
2. Пары с данными могут иметь **неполное покрытие временного диапазона**

### Дополнительные проблемы (обнаружены при анализе)

#### Проблема 2: Неполное покрытие временного диапазона
Даже если для пары есть данные в БД, они могут не покрывать весь запрошенный временной период:
- **Запрос**: с 2022-08-31 до 2025-05-19
- **В БД**: данные только с 2024-01-01 до 2025-05-19  
- **Нужна дозагрузка**: с 2022-08-31 до 2024-01-01

#### Проблема 3: Запрос данных до начала торговли (НОВАЯ)
Торговая пара может начать торговаться позже запрошенной даты:
- **Запрос**: с 2020-01-01 до 2025-05-19
- **Реальное начало торговли SOLUSDT**: с 2021-08-01
- **В БД**: данные с 2021-08-01 до 2025-05-19
- **Старый алгоритм**: "неполное покрытие, нужно дозагрузить 2020-01-01 до 2021-08-01"
- **Реальность**: Период 2020-01-01 до 2021-08-01 не существует!
- **Новый алгоритм**: Проверяем реальный launch time и корректируем диапазон

## Исправление

### Старая логика (неправильная)
```javascript
if (dbDataRatio >= 0.5) { // Если 50%+ пар имеют данные в БД
  // Используем только БД данные, игнорируем отсутствующие пары
  finalCandlesData = candlesFromDB;
}
```

### Новая логика (исправленная v3)
```javascript
// Анализируем каждую пару на предмет необходимости дозагрузки
for (const symbol of portfolioParams.pairSymbols) {
  const candles = candlesFromDB[symbol] || [];
  
  if (candles.length === 0) {
    // Случай 1: Данных нет вообще
    pairsNeedingFetch.push(symbol);
  } else {
    // Случай 2: Данные есть, проверяем покрытие с учетом реального начала торговли
    const firstCandleTime = Number(candles[0].timestamp);
    const lastCandleTime = Number(candles[candles.length - 1].timestamp);
    
    // НОВОЕ: Получаем реальный диапазон торговли
    let actualStartTime = startTimestamp;
    try {
      const tradingRange = await getTradingDateRange(symbol, exchange);
      if (tradingRange.startTime && tradingRange.startTime > startTimestamp) {
        actualStartTime = tradingRange.startTime; // Корректируем начало на реальное
      }
    } catch (error) {
      // Используем запрошенный диапазон при ошибке
    }
    
    // Проверяем покрытие с учетом реального начала торговли
    const missingStart = firstCandleTime > actualStartTime;
    const missingEnd = lastCandleTime < endTimestamp;
    
    if (missingStart || missingEnd) {
      // Неполное покрытие - нужна дозагрузка только реально существующего периода
      pairsNeedingFetch.push(symbol);
    }
  }
}

// Принятие решения о стратегии загрузки (без изменений)
if (pairsNeedingFetch.length === 0) {
  finalCandlesData = candlesFromDB;
} else if (pairsNeedingFetch.length > portfolioParams.pairSymbols.length * 0.5) {
  finalCandlesData = allPairsFromAPI;
} else {
  finalCandlesData = { ...candlesFromDB, ...missingPairsData };
}
```

## Стратегии загрузки данных

### 1. Только БД (оптимальная производительность)
**Условие**: `pairsWithoutData.length === 0`
- Все пары имеют данные в БД
- Никаких API запросов не нужно
- Максимальная скорость выполнения

### 2. Гибридная загрузка (сбалансированная)
**Условие**: `pairsWithoutData.length <= 50% от общего числа пар`
- Используем данные из БД для имеющихся пар
- Догружаем через API только отсутствующие пары
- Комбинируем все данные: `{ ...candlesFromDB, ...missingPairsData }`

### 3. Полная API загрузка (максимальная согласованность)
**Условие**: `pairsWithoutData.length > 50% от общего числа пар`
- Загружаем ВСЕ пары через API для обеспечения согласованности
- Сохраняем все данные в БД для будущих запросов
- Используется когда в БД слишком мало данных

## Преимущества исправления

### ✅ Решенные проблемы
1. **Гарантированная загрузка данных**: Отсутствующие пары всегда загружаются
2. **Точность бэктестов**: Все пары участвуют в симуляции
3. **Оптимизированная производительность**: Минимальные API запросы
4. **Лучшая диагностика**: Подробные логи о стратегии загрузки

### ✅ Сохраненные преимущества
1. **Кэширование БД**: Существующие данные берутся из БД
2. **Производительность**: API запросы только для недостающих данных
3. **Масштабируемость**: Поддержка больших портфолио

- **БД**:

- **Результат**: 3 пары из БД + дозагрузка XRPUSDT + полная загрузка RVNUSDT через API

- **Пары**: 10 новых пар
- **БД**: 3 пары есть, 7 отсутствуют
- **Результат**: Все 10 пар загружаются через API для согласованности
