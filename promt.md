Этап 2: Реализация Логики Стратегии на Backend [ЗАВЕРШЕНО]

Модуль `indicators`: Реализация `calculateATR`, `calculateVolumeProfile`, `calculateNWE`, `calculateApproxDelta`, `calculateAvgVolume`. Функции должны корректно работать с массивами свечей любого из поддерживаемых таймфреймов.
    *   **Примечание по `calculateApproxDelta`**: Текущая реализация `calculateApproxDelta` будет основана на аппроксимации с использованием CLV (Close Location Value) и объема свечи. Это связано с тем, что для точного расчета дельты (разницы между объемами покупок и продаж по каждой цене внутри свечи) необходимы тиковые данные или данные футпринта, которые на данном этапе не используются.
        *   **Будущее улучшение**: При обнаружении потенциального сигнала, где аппроксимированная дельта играет роль, рассмотреть возможность **точечного запроса тиковых данных (или данных футпринта) для конкретной сигнальной свечи** через API биржи для подтверждения/уточнения значения дельты. Это позволит избежать постоянной обработки большого объема тиковых данных, сохранив производительность, но повысив точность в ключевых моментах.
    *   **Кластерный анализ**:
        *   **Источник данных для кластеров**: Первоначально кластеры будут идентифицироваться на основе **аномального объема** на свече.
        *   **Определение значительного кластера**: Порог для определения "значительного" или "аномального" объема будет **динамическим**. Например, он может рассчитываться как объем, превышающий скользящее среднее объема за `N` предыдущих свечей на `X` стандартных отклонений, или как объем, превышающий `Y` раз значение ATR (выраженное в объеме). Конкретный метод и параметры (`N`, `X`, `Y`) будут настраиваемыми.
        *   **Подтверждение кластера**: Логика подтверждения (например, `confirmationBars`) будет применяться после идентификации аномального объема. На данном этапе оставим этот параметр для гибкости, возможно, начальная реализация будет без строгого подтверждения или с простым подтверждением (например, следующая свеча не перекрывает полностью предыдущую в обратном направлении).
    *   **Сборка проекта**: Для решения конфликтов типов Jest при сборке Docker-образа был создан файл `tsconfig.build.json`, который наследует основной `tsconfig.json`, но исключает типы `jest` (используя `types: ["node"]`). Скрипт `build` в `package.json` был обновлен для использования этого конфигурационного файла.

Модуль `strategy`: Функция `applyStrategyLogic`, принимающая свечи и параметры, возвращающая рассчитанные индикаторы и сигнальные флаги для каждой свечи.
    *   **Интеграция кластерного анализа**: `applyStrategyLogic` будет использовать параметры `ClusterSettings` (с `source: 'volume'`, динамическим `thresholdMultiplier` и т.д.) для определения кластерных сигналов.
    *   **Определение торговых сигналов**: Реализованы базовые условия входа в длинные и короткие позиции на основе POC, NWE и кластеров.

Этап 8: Дополнительные Функции и Нововведения (Предложения)
