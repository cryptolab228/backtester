Цель: Разработать высокопроизводительное веб-приложение для бэктестинга, сканирования и потенциальной автоматической торговли торговой стратегии (Dynamic Levels + Cluster Analysis + NWE) на ВСЕХ фьючерсных парах OKX (таймфреймы 15м - 1D) с использованием стека Vue 3 + Node.js. Приложение предназначено для узкого круга лиц и будет развернуто на сервере с CPU Ryzen 5 8400F, GPU RTX 4060 и 150-200GB дискового пространства.

Ключевые требования: Быстрый мульти-таймфреймный Сканнер по всем парам, Параллельный Бектестинг с различными параметрами, Эффективная загрузка и хранение исторических OHLCV данных OKX (15м-1D), Удобный UI (включая Настройки), Современные технологии (Vue 3/Node.js/PrimeVue/Tailwind/PostgreSQL/Redis), Гибкость, Итеративная разработка, Максимальное использование аппаратных ресурсов (многопоточность CPU, ускорение на GPU).

Анализ и Адаптация Стратегии (Pine Script -> JavaScript/TypeScript)

Логика индикаторов (DLC/VP, NWE, Clusters, ATR) и условия входа/выхода остаются прежними, как обсуждалось ранее. Ключевое – точное воспроизведение расчетов на JS/TS.

Технологический Стек (Предлагаемый):

Backend: Node.js + TypeScript, Express.js, PostgreSQL + TimescaleDB (опционально, но полезно для временных рядов), TypeORM, BullMQ + Redis, axios, socket.io, technicalindicators, lodash, (потенциально) `worker_threads` для CPU-параллелизма, `@tensorflow/tfjs-node-gpu` или `gpu.js` для GPU-ускорения.

Frontend: Vue 3 (Composition API) + TypeScript, Vite, PrimeVue, Tailwind CSS, Pinia, Vue Router, ApexCharts.js, axios, socket.io-client.

Этап 2: Реализация Логики Стратегии на Backend (Как в предыдущем плане)

Модуль indicators: Реализация calculateATR, calculateVolumeProfile, calculateNWE, calculateApproxDelta, calculateAvgVolume. Функции должны корректно работать с массивами свечей любого из поддерживаемых таймфреймов.

Примечание по `calculateApproxDelta`: Текущая реализация `calculateApproxDelta` будет основана на аппроксимации с использованием CLV (Close Location Value) и объема свечи. Это связано с тем, что для точного расчета дельты (разницы между объемами покупок и продаж по каждой цене внутри свечи) необходимы тиковые данные или данные футпринта, которые на данном этапе не используются. В будущем, при появлении возможности получать и обрабатывать более гранулированные данные (например, через API биржи или специализированных провайдеров), планируется доработка этого индикатора для повышения точности расчета дельты.

Модуль strategy: Функция applyStrategyLogic, принимающая свечи и параметры, возвращающая рассчитанные индикаторы и сигнальные флаги для каждой свечи.

Убедиться, что расчет размера позиции и SL/TP корректно использует ATR соответствующего таймфрейма.

Рассчитывает базовые метрики (P&L, Trades, Win Rate).

Возвращает metrics и trades_list.

Очередь Задач (BullMQ): Воркер для runBacktest. Воркер должен быть способен обрабатывать множество задач бектестинга параллельно, делегируя вычисления, например, через `worker_threads`.
